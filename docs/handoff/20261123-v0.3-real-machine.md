- 這份單需要的程式分在幾條分支，**全部合併、發佈 alpha 版之後才開工**（發佈由維護者做；版本號以 GitHub Release 為準，以下寫 `0.3.0aN`）：

## [前情提要]

- **LLOP 是什麼**：把一台電腦上的本地模型（LM Studio、Ollama、vLLM）小規模地分給別人用的伺服器＋網頁：帳號、每個帳號自己的 API key、帳號能用哪些模型、列出模型、從本機控制台載入模型。另附一個 **SDK**，讓別人的程式連這台伺服器（經通道、用 API key、自動加解密）。
- **兩台電腦**：
  - **A＝有模型、跑 LLOP 伺服器的電腦**。帳號在 A 的終端機建（`llmop add-user`），不做網頁自助註冊。
  - **B＝其他電腦**，沒有模型；用 SDK、EasyLLM，或建在 EasyLLM 上的 agent 外殼（例如 SYNOX）連 A。
- **API 連結固定**：A 用不會過期的通道（Cloudflare named tunnel＋自己的網域）時，API 連結長期不換，不做自動探索。真的換了，SDK 會回「API 連結已更換，請向服務提供者拿新連結」，使用者用 SDK 的換連結指令（見 SDK.md）換掉。
- **加密的目標是「防君子」**：閘道、通道、紀錄檔、管理網頁、資料檔都看不到對話明文；跑模型的 A 必須解開才能餵給模型（A 的人 dump 記憶體看得到，這是可接受的）。演算法沿用 v0.2 的 HPKE＋Ed25519（`cryptography` 套件），規格在 [../secure/PROTOCOL.md](../secure/PROTOCOL.md)、[../secure/SECURITY.md](../secure/SECURITY.md)。
- **使用者的金鑰**：B 自己產生金鑰對，私鑰不離開 B，只上傳公鑰；SDK 的註冊指令自動做完。
- 指令說明：[../CLI.md](../CLI.md)（`llmop audit` 在 3.12 節）；上一版的真機單：[20261119-171000-v0.2-real-machine-and-release.md](20261119-171000-v0.2-real-machine-and-release.md)；已知風險：[../HANDOFF.md](../HANDOFF.md) 3.3 節。
- 已經驗過的只有一項：一台有 LM Studio 的電腦上，本機 `POST http://127.0.0.1:8781/v1/chat/completions` 能回答（[20261119-MVP-lmstudio-tunnel.md](20261119-MVP-lmstudio-tunnel.md)，那次通道沒開）。

## [任務]

照下面的順序做，每一步記下「通過／失敗＋畫面或輸出（遮掉 key、密碼、API 連結的秘密路徑）」。**需要人親手做的步驟（按按鈕、看畫面、手機網路）列成「請你做」，沒回報就算未通過。**

### 1. 每台電腦開工前（A、B 都做）

1. 收乾淨：每個 repo `git status` 要乾淨；停掉正在跑的 `llmop serve`（在它的視窗按 Ctrl+C）與其他會用到這些套件的程式。
2. `python --version`（Windows：`py -3.11 --version`）要 ≥ 3.11。
3. 安裝或更新到這次的 alpha 版（見「安裝流程」）。

### 2. A（有模型的電腦）

1. 安裝伺服器（見「安裝流程」A）。**成功**：`llmop --version` 顯示 `0.3.0aN`。
2. 打開 LM Studio 或 Ollama，載入一個模型；跑 `llmop check`。**成功**：每一項 OK，列出模型。
3. 本機控制台載入模型（**請你做**）：`llmop serve --open` → 管理員登入 →「LLM 後端」→「列出模型」→ 選一個**未載入**的模型 →「載入模型」。
   **成功**：出現「已載入：…（N 秒）」，再按「列出模型」時那個模型標「已載入」。vLLM 會回「啟動時就決定模型」，這是預期的。
4. 固定的 API 連結：在 Cloudflare 建 named tunnel（自己的網域），`config.yaml` 的 `tunnels.api` 設 `enabled: true`、`mode: named`、`token: env:<放 token 的環境變數名>`、`public_url: https://api.example.com`（換成自己的）；帳號網站的 `tunnels.ui` 同理（另一個主機名）。
   只想先試的話可以用 quick tunnel（`llmop serve --tunnel`），但它每次啟動都換網址，第 3 節的「連結固定」就不適用。
5. 加密用的 worker（第一次）：`llmop worker init`，`config.yaml` 的 `roles` 改成 `[gateway, worker]`；`llmop worker show-key` 抄下 22 個字元的 `key_id`（指紋），**用另一個管道**（當面、訊息）交給 B 的使用者。
6. 建測試帳號：`llmop add-user tester --generate`，記下只顯示一次的密碼，私下交給 B。
7. 啟動：`llmop serve`（設定了 named tunnel）或 `llmop serve --tunnel`。**成功**：橫幅有 Console、Accounts、API link（遮罩版，例如 `https://<api 主機>/k7Q…/v1`，下一行 `Full link : llmop tunnel show-api`）；沒有本機 `/v1` 那一行；Worker 一行有 key_id。完整的 API 連結用 `llmop tunnel show-api` 看（0.3.0a4 起）。
8. `llmop audit exposure`。**成功**：最後一行 `OK`，沒有 `[FAIL]`。有 FAIL 先不要對外，截圖回報。
9. `llmop audit exposure --public`（經通道，要有網路）。**成功**：`[public]` 開頭的每一行都是 PASS。
10. `llmop audit exposure --with-key`。**成功**：「encryption-required key on plain /v1 -> 403」「e2e request without this key's signature -> 403」「revoked key -> 401」都是 PASS；`llmop keys --all` 看得到一把 `llmop-audit (temporary)` 且已撤銷。
11. 本機免 key 測試：`curl http://127.0.0.1:8781/v1/models`。**成功**：回目前的模型。
12. （B 做完第 3 節第 3 步之後）紀錄檔 canary：先把伺服器的輸出存成檔再跑一次：
    - PowerShell：`llmop serve 2>&1 | Tee-Object serve.log`（0.3.0a4 起 serve.log 只有遮罩版 API 連結，不含秘密路徑；測完仍然刪掉）
    - 另一個視窗：`llmop audit canary --scan serve.log`
    - 確認紀錄檔沒有秘密路徑：用 `llmop tunnel show-api` 印出的連結，取主機名後面那一段（秘密路徑），在 serve.log 裡搜尋（`Select-String -SimpleMatch`）。
    **成功**：「encrypted test request went through the gateway」PASS、「test text not found in data and logs」PASS；秘密路徑在 serve.log 裡找不到。

### 3. B（其他電腦）

指令名與參數以 [../SDK.md](../SDK.md) 為準（SDK 由另一個工作包完成）；下面是流程與預期。

1. 安裝 SDK 與 EasyLLM（見「安裝流程」B）。**成功**：`python -c "import llmop.sdk, ntu_easy_llm; print(ntu_easy_llm.__version__)"` 印出 0.6 系列版本。
2. 註冊（會提示輸入密碼，密碼不存檔）：
   `llmop client enroll --account-url https://accounts.example.com --user tester --fingerprint <A 給的 22 字元> --profile home --test`
   **成功**：依序看到「已在這台建立簽章金鑰」「API key 已存在本機」「伺服器指紋相符，已釘選」「測試回覆：…」。
   **出現「指紋不符」**：停下來，跟 A 重新核對指紋，不要繼續。
3. `llmop client self-check --profile home`。**成功**：明文被拒、沒有簽章被拒，兩項都 PASS。
4. 經 EasyLLM 問一句：照 EasyLLM 文件寫一份設定（只放假的變數名，不放 key），用 `llop` 來源、設定檔 `home`。**成功**：印出回覆。
5. （可選）Waterfall：請 A 在本機控制台發一把總額很小（例如 500 tokens）、「加密：可選」的 GUEST key；B 用 SDK 的「只有 key 的明文設定檔」指令存起來（終端機提示輸入，不貼在聊天裡）；EasyLLM 的 waterfall JSON 設定檔把它排第一、`home` 排第二，模式 `auto`，連問幾題。
   **成功**：前幾題由小額 key 回答，之後出現「已改用 home（原因：額度用完）」。沒設 waterfall 時不會換來源（預設 `off`）。
6. 換連結測試：A 跑 `llmop tunnel rotate-api`（或 `--change-host`），B 再問一次。
   **成功**：SDK 回「API 連結已更換，請向服務提供者拿新連結」；用 SDK 的換連結指令換成 A 給的新連結（`llmop tunnel show-api`）後恢復正常。
7. 撤銷測試：A 在本機控制台（或 `llmop revoke-key <ID>`）撤銷 `home` 那把 key，B 再問。
   **成功**：沒有備援時顯示「金鑰失效」；有備援時顯示「已改用 …（原因：金鑰失效）」。測完回到第 2 步重新註冊。
8. agent 外殼（SYNOX，或其他建在 EasyLLM 上的程式）：照那個專案自己的交辦單選「LLOP → 設定檔 home → 模型」，送一句話。**成功**：有回覆，畫面上看得到目前的來源。

### 4. 收尾

- A 用 Ctrl+C 停掉 `llmop serve`（cloudflared 會一起結束）；刪掉 `serve.log`。
- 撤銷測試用的 key 與 GUEST key（`llmop keys --all` 確認）。
- 結果寫進 LLOP 的 [../../HumanTestList.md](../../HumanTestList.md)（打勾、日期、結果）與 [../HANDOFF.md](../HANDOFF.md) 3.3 節；其他專案記在各自的待測清單。

**不要做**

- 不把本機控制台（8781）或 LLM 伺服器的埠（11434、1234…）開給外面、不改路由器或防火牆；對外只走 `llmop serve` 自己的兩個通道。
- 不把 key、密碼、API 連結（含秘密路徑）、`serve.log` 貼到聊天、issue 或 commit；回報時遮掉。
- 不 commit `config.yaml`、`data/`、`$LLMOP_HOME`；不 force push；發佈與推送由維護者做。
- 不改 `docs/BU_Keep_*`、`docs/BU_Keep.sha256`。

## [安裝流程與環境確認]

共同：Python 3.11 以上、git。網址一律換成自己的（下面都是假網址）。

**A（伺服器）**

```bash
git clone <LLOP 的 git 網址> LocalLLMOutsiderProvider
cd LocalLLMOutsiderProvider
git checkout <alpha 版的 tag 或分支>
python -m venv .venv
.venv/bin/pip install -e ".[dev,secure]"        # Windows：.venv\Scripts\pip（SDK 拆套件後以 README 的安裝指令為準）
.venv/bin/python -m pytest -q                   # 開工前基準：記下 passed／failed／skipped 數字
llmop init --backend-type lmstudio --backend-url http://127.0.0.1:1234   # 或 ollama；第一次才需要
```

- 需要：LM Studio（開「Just-in-Time model loading」）或 Ollama，至少一個模型；cloudflared（`winget install --id Cloudflare.cloudflared`）。
- 祕密：named tunnel 的 token 從環境變數讀（設定檔只寫 `env:<變數名>`）；不寫進任何檔案或 commit。
- Windows 的測試基準：這一版起 `pytest -q` 在 Windows 應該 0 failed（有 2 個附理由的 skip：tunnel 的 terminate 測試、需要 `/proc` 的測試）。

**B（其他電腦）**

```bash
python -m venv .venv
.venv/bin/pip install "<LLOP 的 SDK 安裝來源>"            # 例：Release 的 wheel 加 [sdk]，以 SDK.md 為準
.venv/bin/pip install "ntu_easy_llm[llop] @ <EasyLLM 的 Release wheel 網址>"
```

- 不需要模型；不需要任何祕密（密碼在 `enroll` 時現場輸入、不存檔；簽章私鑰在 B 的家目錄，權限只有本人）。
