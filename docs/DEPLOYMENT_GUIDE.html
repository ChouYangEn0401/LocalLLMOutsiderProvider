LocalLLMOutsiderProvider · v0.1

把家裡的本地 LLM 分享出去：五種部署方式

llmop 是一層小小的閘道：它站在 Ollama 或 vLLM 前面，負責登入、API key 和 token 額度，再透過 Cloudflare tunnel 給外面的人用。這頁說明有哪幾種擺法、各要打哪些指令。Docker 不熟也沒關係，最推薦的方式根本不用 Docker。

架設端和應用端

架設端（你）應用端（朋友、你的其他裝置）
要裝什麼llmop（這頁的五種方式之一）、cloudflared、Ollama什麼都不用裝，用現成的 OpenAI SDK、curl、Open WebUI、Cline
拿到什麼公開網址網址 + sk-llop-… API key（登入網頁自己申請）

whl 和免安裝版 zip 都是架設端的安裝檔。whl 是 Python 的「零件」，要先有 Python；zip 把零件連同 Python 一起包好，解壓縮就能用。API 跟 OpenAI 相容，所以應用端不需要我們的任何套件。

流量怎麼走

對外只有 cloudflared 一條路，而且是它主動往外連，所以路由器不用開 port。Ollama 本身沒有密碼，在每種方式裡都不會對外公開。

A

Windows 免安裝版（不用 Docker，不用先裝 Python）

推薦

Ollama 照你平常的方式裝在 Windows 上。llmop 跑在旁邊，同一台電腦用 127.0.0.1 互連，最單純。

  1. 從 GitHub Release 下載 llmop-0.1.0-windows-x64-portable.zip，解壓縮到任意資料夾。
  2. 雙擊 Start-With-Tunnel.bat（只在本機測試用 Start.bat）。第一次會請你設定 admin 密碼；沒有 cloudflared 的話，它會問要不要幫你裝，也可以自己裝： 
    winget install --id Cloudflare.cloudflared
  3. 瀏覽器會自動打開，畫面上也會印出 https://….trycloudflare.com。登入後在「API 金鑰」申請一把 key（只會顯示一次）。
  4. 新增朋友帳號：雙擊 Add-User.bat。其他指令可以在 Command-Prompt.bat 開的視窗裡打，例如： 
    llmop usage

已經有 Python 的話，也可以改用 whl：pip install localllm_outsider_provider-0.1.0-py3-none-any.whl，然後 llmop init、llmop serve --tunnel。

Ollama 預設 context 很小，超過時會悄悄截掉前面的內容。建議在 Windows 的環境變數加上 OLLAMA_CONTEXT_LENGTH=8192，然後重開 Ollama。

B

Docker 只跑 llmop，接 Windows 上的 Ollama

容器裡的程式要連到主機，得用 host.docker.internal 這個名字（Docker Desktop 內建）。以下指令都在專案的 docker 資料夾裡執行。

  1. 複製設定檔，把 backends 的 base_url 改成 http://host.docker.internal:11434： 
    copy config.docker.example.yaml config\config.yaml
  2. 產生 admin 密碼雜湊，貼進 config\config.yaml 的 password_hash： 
    docker compose -f compose.host-ollama.yml run --rm llmop hash-password
  3. 建置並在背景啟動： 
    docker compose -f compose.host-ollama.yml up -d --build
  4. 打開 http://127.0.0.1:8780 登入。
C

llmop + Ollama 都在 Docker

Ollama 在容器網路裡叫 ollama，所以 base_url 是 http://ollama:11434（範例設定檔預設就是這個）。模型存在 ollama-models volume，關掉容器也不會消失。

  1. 複製設定檔： 
    copy config.docker.example.yaml config\config.yaml
  2. 產生密碼雜湊，貼進設定檔： 
    docker compose -f compose.ollama.yml run --rm --no-deps llmop hash-password
  3. 啟動： 
    docker compose -f compose.ollama.yml up -d --build
  4. 在容器裡拉模型： 
    docker compose -f compose.ollama.yml exec ollama ollama pull qwen3.5:9b

要用 GPU：Docker Desktop 選 WSL 2 後端、裝新版 NVIDIA 驅動，再把 compose.ollama.yml 裡註解掉的 deploy: 區塊打開。

D

llmop + vLLM

需 NVIDIA GPU

vLLM 直接從 HuggingFace 載模型，適合多人同時用。設定放在 docker\.env（不會進版控）。

  1. 建立 docker\.env，至少寫上模型： 
    VLLM_MODEL=Qwen/Qwen2.5-1.5B-Instruct
VLLM_MAX_MODEL_LEN=8192
TZ=Asia/Taipei
  2. 複製設定檔，把 backends 換成 vllm 那段（http://vllm:8000），並產生密碼雜湊： 
    docker compose -f compose.vllm.yml run --rm --no-deps llmop hash-password
  3. 啟動。第一次會下載模型，可以看 log 等它好： 
    docker compose -f compose.vllm.yml up -d --build
    docker compose -f compose.vllm.yml logs -f vllm
E

加上公開網址（疊在 B、C、D 上）

在原本的指令後面多加 -f compose.tunnel.yml，就會多跑一個 cloudflared 容器。以 C 為例：

  1. 啟動： 
    docker compose -f compose.ollama.yml -f compose.tunnel.yml up -d --build
  2. 找出公開網址（忽略 api.trycloudflare.com，你的是一串隨機英文字）： 
    docker compose -f compose.ollama.yml -f compose.tunnel.yml logs cloudflared | findstr trycloudflare
  3. 把網址貼到 config\config.yaml 的 server.public_url，存檔就生效。這樣網頁上的範例會顯示正確的網址。

方式 A 不需要這步：llmop serve --tunnel 會自己抓網址，顯示在網頁上，也寫進 data\public_url.txt。

Docker 小辭典

image（映像檔）
打包好的程式加執行環境。--build 會用 docker/Dockerfile 做出 llmop 的 image。
container（容器）
image 跑起來的樣子。可以想成一台小虛擬機，關掉再開，裡面的暫存東西會消失。
compose 檔
一次描述好幾個容器怎麼一起跑。-f 指定用哪個檔，可以疊好幾個。
volume
容器外的永久儲存。用量紀錄、key、模型都放這裡。down 會保留，down -v 會刪掉。
127.0.0.1:8780
只開給這台電腦。外面的人只能透過 tunnel 進來，所以範例都寫這個，不要改成 8780:8780。
host.docker.internal
容器裡用來指「主機（你的 Windows）」的名字。

一定會遇到的問題

重開之後網址變了，朋友怎麼辦？

Quick tunnel 每次啟動都會換一個隨機網址。朋友登入網頁就能看到最新網址；API key 不會因此失效，只要換 base_url。

想要固定網址：在 Cloudflare 免費帳號加上自己的網域，建立 named tunnel，再把 config 的 tunnel.mode 設成 named、token: env:CLOUDFLARE_TUNNEL_TOKEN，並把 server.public_url 填上你的網域。

串流（stream: true）有時候卡住或一次吐出來

Cloudflare 官方文件寫 quick tunnel 不支援 SSE 串流。實際上大多能用，但不保證。llmop 在等待第一個字時會每 15 秒送 keepalive 來減少中斷。真的不穩時改用 stream: false，或改用 named tunnel。

出現 524 錯誤

Cloudflare 大約 100 秒收不到任何回應就會切斷。模型很慢、又沒開串流的時候會遇到。請用串流，或降低 max_tokens。

回答突然變笨、好像忘了前面說過的話

這通常是 Ollama 的 context 太小，前面的內容被靜默截掉了。設定 OLLAMA_CONTEXT_LENGTH（Docker 的話寫在 compose 的 ollama environment 裡）。

額度怎麼算？

每日、每月 token 從資料庫加總，依主機時間的午夜和月初重置。每分鐘請求數和同時請求數記在記憶體裡。請求前會先檢查，再把 max_tokens 壓到剩餘額度，結束後依實際用量記帳，所以單次可能稍微超過一點，跟 OpenAI、LiteLLM 的作法相同。
