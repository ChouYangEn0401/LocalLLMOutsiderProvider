「加密不能換個網址就好嗎？」

可以，而且就是這樣做的。送到 /v1 的是明文，送到 /e2e/v1 的是加密。走哪一條由用戶端決定：有裝外掛的才有能力走加密那一條。不需要選什麼「部署方案」，那個畫面已經拿掉。

但 key 上那個「是否加密」的選項不能省。它管的是准不准。假設沒有它：你把一把 key 給了同事並約好要加密，之後這把 key 外流，或他換了一個沒裝外掛的程式，請求就會默默走明文，沒有任何東西攔下來。有了它，標成「加密」的 key 送到 /v1 會直接被拒絕。

一句話：網址決定怎麼送，key 的選項決定准不准。兩個都要，但使用者只需要在建立 key 時勾一次。

數字怎麼來的

  • 假設一個對話每秒出 30 個 token、伺服器同時跑得動 2.5 個對話、一筆請求平均 1,900 token。算出整台每秒約 260 token，留三成餘裕後可分配 182。
  • 「25 人、每人平均 1.2 個 session」有兩種讀法。讀成「每人每天用 1.2 次」，尖峰約 12 個對話同時在聊，剛好夠用（使用率約 67–80%）。讀成「25 人同時在線、各開 1.2 個視窗」就是 30 個對話，需求是產能的兩倍，一定會排隊。
  • 182 ÷ 12 ≈ 15，這就是每個 NORMAL 帳號長期可以用的速度；乘上 1.5 小時得到 80,000。
  • 一般聊天（每 108 秒一句）的用量是每秒 17.6，只比回復速度高一點，要連續聊 8 小時才會見底。用程式狂送的人 15 分鐘就見底。

訪客 key 與臨時 key

  • 預設不重置：用完或到期就失效。唯讀頁仍然看得到它，顯示失效原因。
  • 你可以在發 key 時勾「每週重置」。有重置的 key 用完只是暫停，不會失效。
  • 訪客不會被降級，也不會升級。

一、現在是怎麼運作的

看得到對話明文的範圍只有密文經過

(a) 一筆聊天請求從頭到尾

A 的重點

  • 驗證、額度、轉送、記帳都在同一個程式裡。
  • 真的串流：後端每吐一段，閘道就轉一段；中途取消也會結算用量。
  • 每筆請求在資料庫記一列：誰、哪把 key、模型、token 數、耗時、成功與否。不記對話內容。

B 的重點

  • 閘道能做的只有：認 key、驗簽章、算額度、挑一台有這個模型的 worker、轉送。
  • 沒有串流：worker 收到串流請求會拒絕；用戶端代理等整段算完再假裝成串流送給應用程式。
  • 等太久不會斷：閘道先等 80 秒，還沒好就請用戶端改用輪詢，避開 Cloudflare 的 100 秒限制。
  • 紀錄只有代號、模型、大小、狀態；有測試禁止把內容寫進紀錄。

(b) 登入 → 拿 key → 使用

A：使用者自助

  1. 你在 config.yaml 開帳號（或用 llmop add-user）。
  2. 朋友開網頁用帳號密碼登入，拿到 12 小時有效的登入狀態（cookie；資料庫只存它的雜湊）。
  3. 他按「申請新金鑰」，sk-llop-… 只顯示這一次；資料庫只存雜湊。
  4. 他在程式裡填網址與 key。API 只認 key，網頁只認登入狀態，兩者不互通。
出處：web/routes.py:467, 613、auth.py:96, 114、security.py

B：管理員發放

  1. 使用者在自己電腦執行 llmop client keygen，產生簽章鑰匙，把公開的那半傳給你。
  2. 你在閘道那台機器開管理頁（預設只接受本機連線），建立 API key 並綁上他的公鑰。
  3. 你把 llmop_sk_… 傳給他；他另外要從 worker 的畫面抄下 worker 公鑰來「釘選」。
  4. 他啟動本機代理，應用程式指向 127.0.0.1:8788。
出處：gateway/admin.py:254, 316、client/config.py、docs/DEPLOY.md §5–6

(c) 額度怎麼算

A：事後記帳（軟性）

  • 以帳號為單位：每日／每月 token、每分鐘／每日請求數、同時請求數、單次上限。
  • 放行前只看「目前已記的用量超過了沒」；算完才把這筆記進去，所以單筆可能略超。
  • 每日額度在主機當地時間午夜重置。
出處：quota.py:119-180、store.py:268

B：先預扣再結算（硬性）

  • 以每把 key為單位：每日請求數、每日 token。
  • 放行前先把這筆的 max_tokens 預留起來，回來再換成實際用量。
  • 以 UTC 換日。用量數字由 worker 明文回報給閘道。
出處：gateway/store.py:257-310、gateway/worker_ws.py:116

  • 每一句話都是獨立加密的。你的程式每次都把整段對話歷史重新送一次。換鑰匙之後，下一句話直接用新鑰匙加密，對話接得下去。
  • B 已經有重疊期。worker 可以同時持有新舊兩把鑰匙，使用者可以同時釘選兩把。舊鑰匙要你明確下指令才會刪。
